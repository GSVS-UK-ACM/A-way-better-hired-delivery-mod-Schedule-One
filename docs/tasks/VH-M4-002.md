# VH-M4-002: Timed physical vehicle transitions

## Claim

Status: `IN_PROGRESS`

Owner: Codex

Branch: `feat/vh-m4-002-timed-vehicle-transitions`

Baseline: `9d7707e0708848c84c5262e21afac8972713c7d1` on `main`

Target: Schedule I `0.4.7f12` IL2CPP

## Goal

Implement the server-owned movement coordinator for one existing assigned vehicle. It must reserve the destination before changing the source vehicle, advance the frozen trip state machine through a short timed transfer, and place the same physical vehicle in the selected loading dock when it is safe.

## Boundaries

- Never create or substitute a vehicle.
- Preserve vehicle GUID, ownership, contents, colour, and save identity.
- Reject missing, unowned, occupied, moving, destroyed, delivery-controlled, mismatched, or otherwise unsafe runtime objects.
- Keep clients from directly changing assignments, reservations, trip state, or vehicle state.
- Revalidate after reservation acquisition and before source detachment.
- Wait without displacing an occupant when the destination is unavailable.
- Restore a known vehicle to a visible safe state during interruption or recovery.
- Leave the manual load and hide/release controls for `VH-M4-003`.
- Leave isolated delivery-conflict and full-mod-set acceptance for M5.

## Acceptance

- `IHandlerAssignmentValidator` resolves the live Handler, exact existing vehicle, owned property, and exact dock identity for each operation.
- `IHandlerMovementCoordinator` uses the assignment and reservation authorities instead of duplicating their state.
- A new server-created trip ID owns the lease and every active transition.
- The legal path is `Idle -> Reserved -> InTransit -> WaitingForBay/Placing -> Placed`.
- The source vehicle remains unchanged until the destination lease and second validation both succeed.
- Transit uses a short game-time duration and a safe hidden or held state.
- Placement updates the destination dock's physical occupancy and restores visibility and physics.
- Cancellation, failure, firing, despawn, load recovery, and unload cannot leave a hidden vehicle or stale lease.
- Dependency-free coordinator tests, pinned API checks, compiled-runtime checks, and an installed in-game test all pass before `DONE`.

## Recovery

The runtime-verified `0.4.7f12-dev14` DLL remains the rollback build. Any rejected movement candidate must be removed from the live install before continuing tests.
